# AI Coop 操作指引

使用主代理已獲授權的當次任務。先評估拆解、啟動與驗收成本；只有有助節省時間或改善成果的分工才派出。不要因為有多個模型就重複所有工作。

先用 `ai_status` 確認所選入口可用。呼叫 `ai_submit` 時提供明確指示、必要且獲授權的材料及驗收條件，只選定當次所需的 UTF-8 檔案。不要掃描整個專案、帳戶、歷史聊天或個人目錄。資料需要送到雲端時，必須符合目前任務的授權與使用者設定。

保留 `job_id`；先繼續獨立工作，再以 `ai_result` 收回全部答案。未完成時可用最多 30 秒的有界等待，不密集輪詢。長答案需讀完所有分頁。不能在必要工作仍未收回時宣稱完成。

`ready_for_review` 只表示模型交付。主代理須核對來源、實際模型、錯誤與檔案差異，執行相關檢查後才整合。模型彼此同意不是來源證據。未知模型名稱保留未知；受阻、截斷或限額結果不能改寫為成功。

採階層式多代理協作：主代理安排工作、收回驗證與整合；工作者提供獨立成果和反例。沒有內建對等辯論或自動裁決引擎，需要交叉查核時另安排有界工作。

模型分工參考偏好為一般主代理 `gpt-6.1-sol`／`ultra`，複雜推理與關鍵判斷 `gpt-6-astra`／`ultra`，使用者可依需求設定。品質及可查核比對優先於省額度。選模由有能力控制模型的主代理／客戶端負責；橋接目前沒有 per-job model／effort，Codex worker 忽略個人設定並禁止巢狀多代理，不能宣稱本 Skill 能自動切換主聊天或使 worker 執行 Ultra。記錄要求與實際模型／模式，未知如實記未知；指定組合不可用時明示限制，不靜默降級。

公開範圍僅為橋接方法與模型分工偏好；個別專案的專業流程、專用技能、資料及實際驗收紀錄不隨此技能發布。

目前分析支援多個入口；研究使用 Antigravity 的有界公開來源工具；程式修改使用 Claude 的獨立副本。這是實作提供的模式，不是模型能力排名。PDF 與其他非文字材料先由主代理提取必要內容。

本機 Qwen 適合短批次的原文擷取、分類、清理與草稿；完整渲染任務上限 12,000 UTF-8 bytes。拆成可核對的小批次，核對來源後才使用。精確算術、排序、統計與固定規則轉換由確定性程式完成。不要自動下載模型、轉送雲端或執行模型產生的程式。

使用穩定 `task_key` 和適當 `scope` 協調跨對話工作。輸入相同可能重用舊結果；時效研究請包含日期或資料版本。`rerun:true` 只能在主代理明確決定重跑時使用，不自動重試或換付費入口。

`previous` 只帶入指定前次工作的答案，不取得其他歷史對話。子任務不能遞迴派工。主代理仍負責連貫上下文、驗收與最後交付。

橋接的執行資料會保留任務輸入、檔案副本與供應商回傳。不要將 runtime、登入輸出或私人任務加入版本庫、公開問題回報與附件。請遵循本庫 README 與 SECURITY 的資料邊界。
